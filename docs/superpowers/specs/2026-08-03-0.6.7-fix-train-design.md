# 0.6.7 — fix-train design: write-path criticals, wake-up truncation, wrap cluster

- **Date:** 2026-08-03
- **Status:** approved (brainstormed with Hazar, sections approved individually)
- **Scope:** issues #41, #42, #47 (write path), #48 + #35 (wake-up), #45, #43, #44
  (wrap), plus live-state remediation and the v0.6.6 release catch-up.
- **Out of scope:** doctor/tooling-noise cluster (#29, #31–#34, #36–#38, #40),
  design-shaped items (#46 cap tuning, #39 memory freshness) — later train.

## Goal / exit criterion

All eight in-scope issues closed with test-first fixes; all known-bad live state
healed (misfiled L1s relocated, flux registered, stranded suggestions drained);
0.6.7 tagged AND published together with the missing v0.6.6 GitHub release; a
fresh-session restart smoke shows the doctrine card surviving an over-budget
wake-up payload.

## Structure: clustered sequential train

Three code clusters run in order, each through the full gate cycle
(ren-planner briefs → TDD subagents → ren-reviewer before chaining). Remediation
runs LAST, deliberately: relocations and suggestion drains go through a queue
whose accept()/conflict paths are proven good, never through the code we know is
broken. Rejected alternatives: parallel issue-per-worktree (clusters share
`lib/memory`; guaranteed conflicts; blows the 3–5 agent cap for no gain) and
single-pass omnibus (unreviewed chained work compounds errors — a subtly wrong
#42 detector change would silently shape #47's fix on top of it).

## Cluster 1 — write-path criticals (#41, #42, #47)

### #41 — suggestions accept() cannot apply quarantine-screen actions (CRITICAL)

`_apply()` in `skills/suggestions/lib/__init__.py` dispatches on kind/action and
handles `page_write`, `promote_to_global`, `refresh_claude_md`,
`review_contradiction` — but not the quarantine screen's `quarantine_release` or
`review_lint_finding`. The fall-through returns `applied: False` yet is treated
as an intentional non-write outcome, so `accept()` still records the decision:
the suggestion is marked accepted while nothing happened (silent strand,
confirmed live 2026-08-03).

Fix:
1. Add a `quarantine_release` handler: `quarantine.release_page` +
   `queue.approve_and_apply` with `who="suggestions:quarantine-release"` — the
   exact path validated by hand during the 0.6.6 smoke.
2. Add a `review_lint_finding` handler applying the lint fix through the queue.
3. Make the unknown-kind fall-through RAISE instead of falling into the decided
   path — a future producer/consumer kind mismatch must strand loudly (pending
   + retryable), never silently. This is the structural lesson of #41.

### #42 — conflict detector self-conflict false positives (HIGH)

The detector (`lib/memory/judge.py`) flags `duplicate`/`supersedes`/
`contradicts` without checking whether the evidence page IS the proposal's own
target. A quarantine-release UPDATE re-writes the page's own content minus the
banner, so it always "duplicates"/"supersedes" itself: 12/14 human releases held
on noise during the smoke; self-entries also pollute genuine holds' conflict
lists (live example: `risk-tiers.md`, 5 self-entries drowning 1 real cross-page
conflict).

Fix: exempt same-page findings for UPDATE proposals at the detector level — an
UPDATE cannot meaningfully duplicate or supersede its own target. Cross-page
findings are untouched.

### #47 — wrap re-run held by the ADD-race guard

`_check_add_race` (`lib/memory/queue.py`) correctly holds an ADD whose target
appeared after proposing — but a wrap re-run for the same session legitimately
re-proposes its own L1. Fix at the proposer: wrap proposes UPDATE when the
session's L1 already exists. The guard itself stays untouched as the backstop.
Sequenced last in the cluster; may reuse #42's same-page reasoning.

### Cluster 1 tests (test-first, from live repros)

- #41: drive a real `quarantine_release` suggestion through `accept()`; assert
  the release actually applied AND an unknown kind leaves the suggestion
  pending (raises, not decides).
- #42: rebuild 2026-08-03's held queue entries as fixtures; assert self-conflicts
  vanish while the `product-vision` vs `monetization` cross-page conflicts
  survive.
- #47: run wrap twice for one session; assert the second proposes UPDATE and
  applies.

## Cluster 2 — wake-up truncation (#48 CRITICAL, #35 rides along)

The final whole-payload budget guard in `compose()`
(`hooks/wake-up/wakeup/__init__.py:1422`) runs tail-keeping
`truncate_text_to_tokens` over the entire payload, whose head is the seed
header + doctrine card — eliding exactly the mandatory section. Confirmed live:
five clamped wake-ups across two wikis on 2026-08-03, char-exact
(ratio 2.1813929 × 5000 = 10906 + 42-char marker = 10948 emitted), zero log
evidence. Trigger: the calibration loop's FIRST persisted sample (06:28Z,
2.18 chars/token from n=1) roughly halved every char budget.

Fix, three parts:
1. **Card survives any over-budget payload.** When over budget, truncate only
   the content sections (`sections[2:]` joined) with the head's cost subtracted
   from `max_tokens`, then re-attach seed header + card in front. The card is
   already bounded (~600 chars via the existing full→compact swap). The shared
   truncator is untouched — same section-local philosophy as the existing
   compact-card fix, applied one layer up.
2. **Loss becomes visible.** Final truncation logs at WARNING with elided char
   count. (Today's clamps were silent; the "loss must be VISIBLE" comment was
   violated at this layer.)
3. **Calibration hardening.** The calibrated ratio only displaces the fallback
   constant at a minimum sample count (≥5); log at WARNING when a ratio change
   moves effective budgets by more than 25%. Band-plausibility alone
   demonstrably wasn't enough.

#35: while in `doctrine_card.py`, replace the truncation pointer phrase
("the full doctrine card, which ships in the plugin") with the actual shipped
file path, so the pointer is followable.

### Cluster 2 tests

- Compose-level: over-budget payload → all four doctrine gates intact in output
  AND truncation logged. Fixture ratio copied from the live 2026-08-03
  `estimator.json` so the regression is the real one.
- Calibration: single-sample ratio does not govern budgets; budget-delta
  warning fires past the threshold.

## Cluster 3 — wrap cluster (#45, #43, #44)

### #45 — L1 misfiled when wrap runs outside the project repo

The plumbing exists (`wrap_session` accepts `project=` and `cwd=`; a resolved
project files the L1 exactly where wake-up reads). The break is the call site:
SKILL.md's documented invocation passes neither, so resolution falls back to
process cwd — the plugin cache dir whenever the runner `cd`s there for its
venv. Four sessions misfiled into global `l1/` this way.

Fix: (a) SKILL.md invocation template passes the session's working directory
explicitly (`cwd=Path("<session-cwd>")`); (b) when resolution still fails, the
wrap screen states loudly that the L1 filed under global `l1/` and from what
path detection ran — silent degradation is what let four sessions misfile
unnoticed; (c) `detect_project` itself unchanged — the fix is feeding it the
right input, not another heuristic.

### #43 — L1 frontmatter omits `type:`

The overview and open-work writers emit `type:` lines; the L1 writer doesn't,
so wiki-lint flags every wrap's own output. Fix: emit `type: l1`. The test
doubles as the lint regression (a fresh wrap's L1 passes lint clean).

### #44 — ghost "Saved this session" entries

`render_wrap_screen` lists queue entries with `status == "applied"`, but a
reverted write keeps that status — only the journal records the revert. The
screen offers "undo w-…" for already-undone writes. Fix: filter against the
journal's revert records in the screen module (which already reads the
session's entries). No new status value, no schema change, no migration.

### Cluster 3 tests

- #45: `wrap_session` with process-cwd in a fake plugin dir + explicit `cwd=`
  in a repo → L1 lands in `projects/<slug>/l1/`; and the loud-fallback message
  renders when neither resolves.
- #43: fresh wrap's L1 frontmatter contains `type: l1`.
- #44: apply a write, revert it, render screen → entry absent.

1. **L1 audit + relocation.** Global `l1/` holds five files.
   `session-flux-mac-setup-2026-08-03.md` → flux. The three UUID-named ones get
   their owning project determined from content (`session-ecb4330c` is ren-os
   per its lint suggestion). `session-ren-install-2026-07-31.md` likely stays
   global legitimately (install session, pre-project). Each relocation goes
   through the queue — ADD to `projects/<slug>/l1/` + removal of the global

   detection works even before anyone reads the fixed SKILL.md).
3. **Drain stranded interactive state as live verification.** The 13 pending

   release actually applying is the end-to-end proof. The 6 contradiction
   holds remain Hazar's judgment calls, re-rendered noise-free after #42
